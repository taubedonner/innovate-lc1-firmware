# Разбор образа в Ghidra

Здесь то, чего не хватает штатной Ghidra, чтобы открыть дамп ATmega64A и
повторить разбор. Сам двоичный образ прошивки в репозиторий не входит,
снимите его со своего прибора.

## Язык avr8:LE:16:atmega64a

В поставке Ghidra ATmega64A нет. Нужно добавить один блок в
`Ghidra/Processors/Atmel/data/languages/avr8.ldefs`:

```xml
<language processor="AVR8" endian="little" size="16"
          variant="atmega64a" version="1.3"
          slafile="avr8.sla" processorspec="atmega64a.pspec"
          manualindexfile="../manuals/AVR8.idx"
          id="avr8:LE:16:atmega64a">
  <description>AVR8 ATmega64A</description>
  <compiler name="gcc" spec="avr8gcc.cspec" id="gcc"/>
  <external_name tool="gnu" name="avr:51"/>
  <external_name tool="IDA-PRO" name="avr"/>
</language>
```

**Дописать блок, а не подменять файл целиком.** Готовые `avr8.ldefs` из
чужих сборок обычно старее вашего и молча выкидывают язык
`avr8:LE:24:xmega`, а `avr8:LE:16:atmega256` понижают с версии 1.4 до 1.3
(`size` 24 -> 16, `avr8eind.sla` -> `avr8e.sla`, то есть без поддержки
EIND). Работа с Xmega и ATmega256x после такой подмены ломается.

`atmega64a.pspec` из этого каталога положите рядом, в тот же
`data/languages/`. Он сделан из штатного `atmega328.pspec`: адресные
пространства, карта регистров ввода-вывода и таблица из 35 векторов
приведены к ATmega64A. Без него можно дизассемблировать, но декомпилятор
запускать не стоит - он будет считать периферию не по тем адресам.

## Скрипты

```sh
analyzeHeadless <каталог_проекта> <имя_проекта> -process "<имя_программы>" \
    -noanalysis -readOnly -scriptPath tools/ghidra -postScript LC1Probe.java
```

* `LC1Probe.java` - карта блоков памяти, все ссылки на диапазон ОЗУ
  `mem:0x0100..0x0209` с именами функций-источников, символы в этом
  диапазоне и счётчик функций с осмысленными именами. Именно так
  проверялось, что переменные с соседними адресами используются одной и
  той же группой функций.
* `LC1Funcs.java` - список всех функций: адрес, размер в байтах, имя.
  Удобно сверять покрытие: сумма размеров против размера секции кода.

## Восстановление проекта из архива .gar

GAR - обычный ZIP:

1. распаковать в каталог;
2. создать `<Имя>.rep/`, положить туда `idata`, `user`, `versioned`;
3. добавить `<Имя>.rep/project.prp` и пустой `<Имя>.gpr` - их проще взять
   из пустого проекта, созданного через `analyzeHeadless <dir> <name>
   -import <файл>`.

## Чего ждать от имён в декомпиле

Из имён функций, которые Ghidra проставляет сама, доверять можно только
отмеченным как FID (Function ID) - в этом образе таких восемь, и все они
из библиотеки компилятора. Остальные осмысленные имена в чужих проектах
проставлены руками аналитика и являются догадками: их надо перепроверять
по коду, а не принимать на веру.
